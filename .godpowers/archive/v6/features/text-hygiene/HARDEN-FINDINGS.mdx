## Findings

### [MEDIUM-001] File input follows symlinks and can block on non-regular files

- **Category**: OWASP A01:2025 Broken Access Control and A10:2025 Mishandling of Exceptional Conditions
- **Original Location**: `scripts/text_hygiene.py:568-574` before repair
- **Original Description**: Path input followed a final-component symlink and opened FIFOs or other non-regular files before validating the input type.
- **Original Impact**: A repository-controlled or mistaken pathname could disclose an unintended caller-readable file to the downstream model or block the local hygiene stage indefinitely.
- **Original Reproduction**: Invoke `clean` against a temporary final-component symlink to a file containing `secret-marker`, then invoke it against a FIFO with no writer and a 0.5 second harness timeout.
- **Original Observed Result**: The symlink returned 0 and emitted `secret-marker`. The FIFO blocked past 0.5 seconds.
- **Repair**: `_open_regular_file` now uses `lstat`, rejects non-regular paths, opens with `O_NOFOLLOW` where available, checks the opened descriptor with `fstat`, and verifies device and inode identity before reading.
- **Reverification**: Repeated the original symlink and FIFO probes. Both returned exit 2, emitted zero stdout bytes, and reported `path input must be a regular file and not a symbolic link`. The FIFO result returned in 31.4 ms rather than timing out.
- **Regression Evidence**: `tests/test_text_hygiene.py:412-442`; implementation at `scripts/text_hygiene.py:563-590`.
- **Reviewed At**: 2026-08-14T14:07:25Z
- **Owner**: Voiceprint maintainer
- **Due**: Resolved 2026-08-14
- **Status**: Fixed

### [MEDIUM-002] Unicode preservation heuristics accept unsupported hidden sequences

- **Category**: OWASP A08:2025 Software or Data Integrity Failures
- **Original Location**: `scripts/text_hygiene.py:409-474` before repair
- **Original Description**: Supplementary variation selectors were preserved after any supported complex-script letter, and recombined emoji ZWJ chains were described as valid sequences based only on pairwise evidence.
- **Original Impact**: Unsupported hidden formatting could survive cleanup with an overly strong preservation reason, weakening the integrity report.
- **Original Reproduction**: Process Arabic Alef followed by U+E0100, then process five U+1F468 bases joined by four U+200D characters.
- **Original Observed Result**: U+E0100 was preserved and labeled as a complex-script glyph selector. The recombined chain was preserved and its ZWJs were labeled as joining a valid emoji sequence.
- **Repair**: Supplementary selectors and unsupported selector contexts are removed. Mongolian selectors and FE0E or FE0F use narrower documented contexts. Emoji ZWJ reasons now state only `matches a pinned Emoji 17 pair`, accurately describing the evidence without asserting complete-sequence validity.
- **Reverification**: Arabic Alef plus U+E0100 cleaned to Arabic Alef alone; the manifest recorded U+E0100 as `remove`, count 1. The recombined man chain remained unchanged under the conservative pair policy, but all four ZWJs reported `matches a pinned Emoji 17 pair`, and the reason contained no validity claim.
- **Regression Evidence**: `tests/test_text_hygiene.py:127-170`, `tests/test_text_hygiene.py:235-247`; implementation at `scripts/text_hygiene.py:414-465`; policy disclosure at `README.md:98-109`.
- **Reviewed At**: 2026-08-14T14:07:25Z
- **Owner**: Voiceprint maintainer
- **Due**: Resolved 2026-08-14
- **Status**: Fixed

### [MEDIUM-003] Changed CI executes feature code without immutable action identities or explicit token scope

- **Category**: OWASP A03:2025 Software Supply Chain Failures
- **Original Location**: `.github/workflows/vendor-sync-check.yml:17-39` before repair
- **Original Description**: The workflow used mutable major action tags and did not declare a token permission scope before executing repository-controlled feature tests.
- **Original Impact**: A compromised action tag or unexpectedly broad repository token default could expand the CI supply-chain execution path.
- **Original Reproduction**: Inspect the workflow action references and search for a workflow or job `permissions` declaration.
- **Original Observed Result**: `actions/checkout@v4` and `actions/setup-python@v5` were mutable references, and no explicit permissions block was present.
- **Repair**: The workflow declares `permissions: contents: read` and pins both actions to full 40-character commit SHAs.
- **Reverification**: The workflow contains the read-only permission block. `git ls-remote --tags` against the official repositories resolved checkout SHA `11d5960a326750d5838078e36cf38b85af677262` to tags `v4` and `v4.4.0`, and setup-python SHA `a26af69be951a213d495a4c3e4e4022e16d87065` to tags `v5` and `v5.6.0`.
- **Regression Evidence**: `.github/workflows/vendor-sync-check.yml:17-30`; `tests/test_text_hygiene.py:532-544`.

### [LOW-001] Regular-file precheck can race with replacement by a FIFO

- **Category**: OWASP A10:2025 Mishandling of Exceptional Conditions
- **Original Location**: `scripts/text_hygiene.py:563-579` before repair
- **Original Description**: `_open_regular_file` checked the path with `lstat` and then opened it without `O_NONBLOCK`. A process with directory write access could replace the checked regular file with a FIFO and block `os.open` before post-open validation.
- **Original Impact**: A concurrent local actor could stall the hygiene subprocess through a narrow check-then-open race.
- **Original Reproduction**: In an isolated subprocess, create a temporary regular file, replace the module's `os.lstat` with a fault-injection wrapper that records the original regular-file stat, replaces the path with a FIFO, and returns the recorded stat, then call the CLI with a 0.5 second harness timeout.
- **Original Observed Result**: The subprocess remained blocked until killed after 0.5 seconds and did not reach post-open validation.
- **Repair**: `_open_regular_file` now adds `O_NONBLOCK` where the platform exposes it, before opening and validating the descriptor. The existing `fstat`, regular-file, device, and inode checks then reject a swapped FIFO without reading it.
- **Reverification**: Repeated the exact replacement fault injection under a 1 second timeout. The subprocess returned exit 2 in 36.3 ms, emitted zero stdout bytes, and reported `path input must be a regular file and not a symbolic link`. A separate ordinary regular-file probe returned 0, cleaned U+200B and U+00A0 as expected, and left the source file unchanged.
- **Regression Evidence**: `tests/test_text_hygiene.py:444-479`; implementation at `scripts/text_hygiene.py:563-591`.
- **Reviewed At**: 2026-08-14T14:12:13Z
- **Owner**: Voiceprint maintainer
- **Due**: Resolved 2026-08-14
- **Status**: Fixed
