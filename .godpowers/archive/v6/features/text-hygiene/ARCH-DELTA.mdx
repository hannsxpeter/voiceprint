# Text Hygiene Architecture Delta

## Scope

[DECISION] This delta implements P-MUST-01 through P-MUST-09 from the feature PRD. It adds one deterministic Unicode hygiene operation inside Voiceprint Step 2. It does not add another model-backed transformation, a detector target, file metadata handling, or a media pipeline.

## ADR-001: Use a local standard-library hygiene helper

- [DECISION] Add `scripts/text_hygiene.py` as the sole implementation of Unicode inspection and cleanup.
- [DECISION] Use Python 3 standard-library modules only. The helper makes no network calls and has no telemetry.
- [DECISION] Expose both an importable API and two CLI operations: `inspect` and `clean`.
- [DECISION] `inspect` reports deterministic findings. `clean` writes cleaned text to standard output and can write machine-readable statistics to standard error.
- [DECISION] The helper never rewrites a source file in place.
- [DECISION] Keep all feature code outside `vendor/`.

Rationale: one implementation gives every adapter the same code-point policy and is small enough to audit. Reusing the linked project's broad skill or external image backends would add unrelated behavior and conflict with Voiceprint's product boundary.

## ADR-002: Preserve the public one-pass sequence

The runtime sequence becomes:

1. Capture the submitted text as the immutable original.
2. Run the before authenticity diagnosis once on the immutable original.
3. At the start of Voiceprint Step 2, inspect and clean the immutable original once with `scripts/text_hygiene.py`.
4. Pass the cleaned working copy to the vendored humanizer exactly once.
5. Run the residual authenticity diagnosis exactly once on the final `After` text.
6. Stop and report.

[DECISION] Deterministic cleanup belongs inside the existing transformation stage. It is not a prose rewrite and does not change the count of model-backed transformations.

[DECISION] The six top-level result sections remain unchanged. `Before` remains byte-for-byte identical to the submission. The hygiene manifest is summarized inside `What changed` before the humanizer report.

[DECISION] A poor residual result never triggers another cleanup or rewrite.

## Unicode policy

[DECISION] The default policy removes free-floating hidden formatting controls and replaces Unicode space variants with U+0020. It preserves tabs, carriage returns, line feeds, ordinary visible characters, valid complex-script joiners, and valid emoji joiner or selector sequences.

[DECISION] The default policy does not perform NFKC normalization and does not map confusable letters. These operations can change visible language and identity.

[DECISION] Findings use zero-based Python code-point offsets, not byte offsets. Ordering is by first occurrence. Every finding records code point, Unicode name, action, count, up to 10 offsets, and a plain preservation reason when applicable.

## Failure behavior

[DECISION] Invalid UTF-8 file input, unreadable input, or an internal helper error stops the hygiene stage before humanizer runs. Voiceprint must report that the input was not changed and must not claim cleanup succeeded.

[DECISION] The helper returns exit code 0 when inspection finds nothing or cleanup succeeds, 1 when inspection finds actionable characters, and 2 for usage or processing errors.

[DECISION] Temporary input used for pasted text must be created in a narrowly scoped temporary path and removed after use. A user-provided file is read only unless the user separately asks to persist the final `After` text.

## Verification strategy

- [DECISION] Unit fixtures cover soft hyphens, zero-width controls, bidi controls, tag characters, variation selectors, interlinear controls, exotic spaces, tabs, line breaks, valid complex-script joiners, valid emoji sequences expressed through escapes, fullwidth letters, and Cyrillic lookalikes.
- [DECISION] CLI tests cover standard input, file input, JSON inspection, clean output, exit codes, and invalid UTF-8 failure.
- [DECISION] A performance test processes 100,000 code points and asserts completion within the PRD budget on the local runner without enforcing a flaky CI wall-clock threshold.
- [DECISION] Eval cases assert the immutable `Before`, one cleanup, one humanizer rewrite, one residual diagnosis, six sections, and provenance-neutral language.
- [DECISION] Existing vendor header checks remain unchanged and must pass with no feature-authored changes under `vendor/`.

## Trust boundaries and risks

- [DECISION] User text is untrusted input. The helper treats it only as Unicode data and never evaluates it as code or a shell argument.
- [DECISION] The helper has no network or external process boundary.
- [DECISION] The main correctness risk is removing load-bearing Unicode. Context-sensitive preservation and explicit fixtures mitigate that risk.
- [DECISION] The main product risk is implying detector evasion. Scope text and eval assertions prohibit vendor attribution, detector claims, and passing-score promises.
