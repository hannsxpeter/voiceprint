# Text Hygiene Feature Requirements

## 1. Problem Statement

[DECISION] Writers who paste prose into Voiceprint can unknowingly carry invisible Unicode controls or exotic spacing that survives the current diagnose, rewrite, and residual sequence, while the existing `Before` contract gives them no explanation of those hidden characters.

[DECISION] Voiceprint must make those text-only artifacts inspectable and cleanable without altering the original shown to the writer, adding another prose rewrite, or turning the product into a watermark-removal or detector-evasion tool.

[HYPOTHESIS] A conservative deterministic hygiene stage will remove copy-and-paste artifacts without changing visible meaning; this will be validated before release with exact-output fixtures covering removable, normalizable, and contextually preserved Unicode sequences.

## 2. Target Users

[DECISION] Primary: writers, editors, and documentation authors who invoke Voiceprint through a supported AI coding tool, provide copied Unicode prose, and want one humanizer rewrite plus an honest before-and-after read.

[DECISION] Secondary: Voiceprint maintainers who need auditable behavior that produces identical inspection and cleanup results across supported host tools without modifying the vendored humanizer or authenticity-check skills.

## 4. Functional Requirements

### MUST (feature release blockers)

- P-MUST-01 [DECISION] Voiceprint must preserve the submitted text byte-for-byte in `Before` and run the before authenticity diagnosis on that original text before any cleanup. -- Acceptance: a fixture containing removable invisible characters appears unchanged in `Before`, and the before diagnosis receives the same code-point sequence as the submission.
- P-MUST-02 [DECISION] During the existing Step 2 transformation stage, Voiceprint must inspect the original text deterministically and record each actionable character by `U+XXXX` code point, Unicode name, action class, total count, and up to 10 zero-based code-point offsets. -- Acceptance: repeated inspection of the same fixture produces an identical ordered manifest without a model call, network call, or vendor attribution.
- P-MUST-03 [DECISION] The default cleanup must remove free-floating soft hyphens, zero-width and format controls, bidi directional controls, tag characters, variation selectors, interlinear annotation controls, and other non-orthographic `Cf` characters, and it must replace Unicode space homoglyphs with U+0020 while preserving tabs and line breaks. -- Acceptance: fixtures for every listed class produce the exact expected cleaned working copy and per-class removal or replacement counts.
- P-MUST-04 [DECISION] The default cleanup must preserve contextually load-bearing joiners and selectors in complex-script orthography and valid emoji sequences, and it must not apply NFKC normalization or replace lookalike letters. -- Acceptance: fixtures with non-Latin script joins, valid emoji glue, fullwidth letters, and Cyrillic lookalikes retain their expected code points and are identified as preserved or non-actionable.
- P-MUST-05 [DECISION] Voiceprint must pass exactly one cleaned working copy into exactly one invocation of the vendored humanizer, with no statistical-watermark rewrite, candidate generation, score target, or second prose transformation. -- Acceptance: an instrumented feature eval observes one hygiene cleanup and one humanizer invocation even when the user requests continued rewriting or a target residual score.
- P-MUST-06 [DECISION] Voiceprint must run exactly one fresh residual authenticity diagnosis on the final `After` text and must not use that diagnosis to trigger cleanup or rewriting. -- Acceptance: a fixture with a poor residual still ends after one residual report and retains a single `After` artifact.
- P-MUST-07 [DECISION] Voiceprint must retain the six existing top-level output sections and report text hygiene inside `What changed`, including detected, removed, normalized, and deliberately preserved counts plus an explicit zero-finding result when applicable. -- Acceptance: output matches `Before`, `Authenticity read (before)`, `After`, `What changed`, `Residual (after one pass)`, and `What remains is a human's call`, with no seventh top-level section.
- P-MUST-08 [DECISION] Voiceprint must describe the hygiene result as deterministic Unicode cleanup only and must not claim that a watermark, vendor provenance signal, or detector signal was found or removed. -- Acceptance: zero-hit and positive-hit evals distinguish observable code-point actions from unknown provenance and make no detector-passing promise.
- P-MUST-09 [DECISION] The feature must behave consistently through every supported Voiceprint adapter without editing any file under `vendor/`. -- Acceptance: adapter instructions route to the same root contract, vendor-header validation passes, and `git diff -- vendor/` contains no feature-authored changes.

### SHOULD (feature release if time permits)

- P-SHOULD-01 [DECISION] The hygiene report should name why a suspicious-looking character was preserved when context makes it load-bearing. -- Acceptance: preserved script-joiner and emoji-glue fixtures include a short preservation reason without exposing the invisible character as an unlabeled glyph.

### COULD (post-release)

- P-COULD-01 [HYPOTHESIS] Voiceprint could expose the same inspection manifest as machine-readable JSON for host integrations without changing the human output contract. -- Acceptance: an opt-in mode emits a versioned JSON object whose counts and offsets match the human report, and default Voiceprint output remains unchanged. -- Validation: confirm at least 2 host-integration requests before scheduling implementation.

| Compatibility | [DECISION] Existing no-hit Voiceprint inputs must retain the current six-section contract and exactly one humanizer invocation. | [DECISION] Text hygiene extends the orchestrator without replacing its method. |

## 6. Scope and No-Gos

### In scope for this feature

- [DECISION] Deterministic inspection of invisible Unicode and exotic spaces in user-supplied text.
- [DECISION] Conservative cleanup into a working copy used by the existing single humanizer rewrite.
- [DECISION] Honest action reporting inside the existing `What changed` section.
- [DECISION] Focused eval fixtures and adapter-contract updates outside `vendor/`.

### Explicitly not in scope

- [DECISION] No statistical or token-sampling watermark detection, rewriting, candidate generation, back-translation, or lexical-divergence optimization.
- [DECISION] No AI detector targeting, detector score optimization, attribution of hidden characters to a vendor, or guarantee that any external check will pass.
- [DECISION] No C2PA, EXIF, XMP, document-property, frontmatter-provenance, or other file metadata inspection or removal.
- [DECISION] No image, audio, video, pixel-scoring, or pixel-regeneration pipeline.
- [DECISION] No direct edits under `vendor/`, and no changes to canonical humanizer or authenticity-check criteria in this repository.
- [DECISION] No change to standalone rewrite-only or diagnosis-only routing.
- [DECISION] No additional humanizer pass, residual-driven cleanup, or silent in-place rewrite of a user-provided file.

## 7. Appetite

[DECISION] Time budget: one focused implementation increment of no more than 5 engineering days from architecture approval to verified feature output.

[DECISION] Resource budget: one implementer and one independent reviewer, with no paid service, external model, or new runtime dependency required for hygiene behavior.

[DECISION] Technical constraints: preserve the prompt-skill distribution model, keep hygiene deterministic and dependency-free, keep all feature code outside `vendor/`, and preserve pre-existing working-tree changes.

[DECISION] Product route: primary form is CLI or SDK, product archetype is none evidenced beyond a developer-facing prompt skill, industry overlay is none evidenced, and regulatory overlay is none evidenced.

[DECISION] Completion evidence: a clean consumer fixture must exercise input, inspection, cleanup, the one humanizer rewrite, the final output contract, and the eval assertions without relying on repository internals.
